# Migration pattern

Schema changes go through numbered SQL files under `backend/migrations/`.
There is **no ORM auto-migration** — the numbered files are the only
source of schema truth, and `sqlc` reads the same files to generate typed
Go (see the "sqlc queries" section below).

## Prerequisites

`make db:create` and `make db:migrate` shell out to the `migrate` CLI
(golang-migrate). Install it once per dev machine:

```bash
brew install golang-migrate
# or
go install github.com/golang-migrate/migrate/v4/cmd/migrate@latest
```

If the binary isn't on `PATH`, hand-create the two numbered files under
`backend/migrations/`: `NNN_descriptive_name.up.sql` and the matching
`.down.sql`, where `NNN` is one past the highest existing index.

## Creating a migration

```bash
make db:create NAME=add_orders_table
```

This produces two files:

```
backend/migrations/000NN_add_orders_table.up.sql
backend/migrations/000NN_add_orders_table.down.sql
```

## Rules

- Every up migration has a matching down migration (or `-- irreversible`
  with a clear comment explaining why).
- Prefer additive changes. Adding a NOT NULL column to a populated table
  requires a three-step dance: add nullable → backfill → alter to NOT NULL.
- Parameterized names only — migration names are free text but should be
  short and describe intent (`add_orders_role_column`, not `fix1`).
- Never include seed data in migrations. Use `make db:seed` (and
  `backend/cmd/seed/main.go`) for dev data.

## Rolling out

```bash
make db:migrate   # apply pending
make db:rollback  # roll back one
make db:reset     # drop + migrate (destroys data, DEV ONLY)
```

## sqlc queries

Persistence is sqlc, not an ORM. The flow when a schema change adds or
changes a table:

1. Write the migration (above). `backend/sqlc.yaml` points its `schema`
   at `migrations/`, so sqlc learns column types from the same files
   golang-migrate applies at runtime — keep them in lockstep.
2. Add hand-written queries under
   `backend/internal/adapter/persistence/query/*.sql`. Each query gets a
   `-- name: Verb :one|:many|:exec|:execrows` annotation; the name becomes
   a method on `db.Queries`.
3. Run `make gen:sqlc` (wraps `sqlc generate`). It regenerates the typed
   Go under `backend/internal/adapter/persistence/db/` — **generated, never
   hand-edited** (`// Code generated by sqlc. DO NOT EDIT.`). Commit it.
4. Add a repo method in `user_repo.go` / `session_repo.go` (or a new
   `<entity>_repo.go`) that calls the generated method and maps the row to
   a domain entity via a helper in `models.go`.

Type mapping is configured once in `sqlc.yaml` `overrides` — UUIDs map to
`string`, nullable columns to pointers (`*string`, `*time.Time`) — so the
row structs map to domain with trivial helpers. Domain entities in
`internal/domain/` stay free of any persistence tags or sqlc types; the
`db` package is imported only by `internal/adapter/persistence/`.

`sqlc` is a dev-time tool (like `migrate`): install it once with
`go install github.com/sqlc-dev/sqlc/cmd/sqlc@latest`. Because the
generated code is committed, a fresh clone builds without it — you only
need it when you change a query.
